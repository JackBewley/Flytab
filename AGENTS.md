# Flytab project

The canonical working directory is `/Users/jackbewley/Projects/_creativemethod/Flytab`. The user designated this directory for all future Flytab development. Work on the source files at this root; `dist/` contains a packaged snapshot.

Read README.md and TESTING.md before changing behavior. This is a plain JavaScript Manifest V3 extension with no runtime dependencies or build step. Run `npm test` for unit tests; tests/browser.mjs documents the optional isolated-browser suite. Current v0.3.0 test evidence is in test-evidence/0.3.0; evidence from the initial build remains in test-evidence/2026-09-29.

Preserve the minimal permission and privacy model: tabs, storage, favicon; no host permissions, content scripts, external network requests, analytics, or incognito. Outside the list, Option+F must toggle the previous MRU tab immediately with no popup or release dependency. The toolbar always toggles immediately. The visual flow is hold Option+Shift, press F to open, keep BOTH modifiers held while tapping F to advance, release both to commit and close. Shift NEVER reverses F. Both existing commands advance inside the list and wrap. Escape must cancel while modifiers remain held. Enter/click remain fallback commit paths. Preview never activates or reorders tabs. Capture modifier releases before the UI module loads and commit only when all modifier flags are false. Releasing F while modifiers remain held must not commit. Chrome owns modified F presses; do not handle them twice. Do not claim recovery of releases that happen before the popup receives input, and do not guess modifier state with a timer. Retain command IDs for saved bindings: switch-next toggles outside the list, switch-previous opens it, and both advance inside it. The user explicitly rejects a separate helper app.

DESIGN.md and PRODUCT.md describe the existing product. Test artifacts and browser profiles are development materials and should not enter distribution packages.
